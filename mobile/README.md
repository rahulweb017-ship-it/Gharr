# Gharr Android app

The Expo / React Native client for Gharr. It uses the same `/api/v1` backend as the web app. The first release covers materials shopping, labour hiring, the Estimate Engine with its bill of quantities, and account and addresses.

## How it fits together

- **Routes** live in `src/app/`, using expo-router.
  - `(app)/` is only reachable when signed in; `login.tsx` is the only screen outside it.
  - `(app)/(tabs)/` holds the five tabs: Home, Estimate, Shop, Labour and Profile.
- **API** code is in `src/api/`.
  - `client.ts` sends `x-gharr-client: mobile` and a Bearer token on every request. When a request gets a 401, it refreshes the token once, shared by all in-flight requests, and retries.
  - `types.ts` holds the response shapes, traced from `../src/server/services`.
- **Tokens:** the refresh token is kept in SecureStore; the access token is held in memory only (`src/auth/token-store.ts`).
- **Shared code:** the web app's platform-free code is imported from `../src/shared` (money, phone, units, trades, the zod contracts) using the same `@/shared/*` path. `metro.config.js` watches that folder and resolves `zod` from this app's `node_modules`.

## Run it in development

1. Start the backend so it listens on your LAN. `APP_BASE_URL` must match the port, because the mock payment webhook posts to it:

   ```sh
   # repo root
   APP_BASE_URL=http://localhost:3100 npm run dev:lan
   ```

2. Build and launch the dev client on a phone (with USB debugging on) or an emulator:

   ```sh
   cd mobile
   npm run android        # expo run:android
   ```

   The app works out the backend address from the Metro host: your LAN IP on a phone, `10.0.2.2` on the emulator. You can override it with `EXPO_PUBLIC_API_URL` (see `.env.example`).

3. Sign in with any number starting `90000000`. With `SMS_PROVIDER=console`, the login screen shows the dev code `000000`.

## Build an installable APK

The JS bundle is embedded in the APK, so it runs without Metro. The backend URL is fixed at build time:

```sh
cd mobile
EXPO_PUBLIC_API_URL=http://<your-pc-lan-ip>:3100 npm run build:apk
# -> android/app/build/outputs/apk/release/app-release.apk
```

- Gradle needs `ANDROID_HOME` set (on this PC: `C:\Users\rahul\AppData\Local\Android\Sdk`). Prebuild wipes `android/local.properties`, so don't rely on that file.
- `android/` is generated by `expo prebuild` and is gitignored. Change native settings in `app.json`, not in `android/`.
- The release build is signed with the debug keystore. That's fine for sideloading, but the Play Store needs a real upload key; EAS can manage one (`npx eas-cli@latest build -p android`).
- `usesCleartextTraffic` is on so the APK can talk to a plain-HTTP dev backend. Turn it off once the API is served over HTTPS.

## Checks

```sh
npm run typecheck && npm run lint && npm run export:android
```

## Not in v1

- **Real online payments.** The server's Razorpay provider is still a stub. Online payments go through the dev mock gateway, which the app calls directly.
- **Push notifications.** There is no FCM or device-token backend yet.
- **Support tickets, and the worker and vendor sides of the app.**
